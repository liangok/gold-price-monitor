# GoldPrice Android App · 设计文档

> 目标用户：预算 7~8 万、准备买结婚五金、想避开阶段性高点的人。
> 设备：小米 13 Ultra（Android 13 / HyperOS）。

## 一、技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 语言 / UI | Flutter + Material 3 | 一套代码以后可给对象的 iPhone 用 |
| 状态管理 | Riverpod | 编译期安全，异步状态（加载/错误/缓存）表达好 |
| 图表 | fl_chart | 轻量、活跃；如需更精美可换 syncfusion_flutter_charts |
| 网络 | dio | 拦截器、超时、重试方便 |
| 本地缓存 | drift (SQLite) | 离线可看，避免每次启动都请求网络 |
| 后台任务 | workmanager | 定时检查策略并在触发时发通知 |
| 通知 | flutter_local_notifications | 通知栏推送 |
| 最低版本 | Android 8.0 (API 26) | 覆盖面够，代码简单 |

## 二、数据获取

App 不直接抓第三方网页，只读我们自己的 GitHub 仓库（由 GitHub Actions 每日更新）：

```
https://raw.githubusercontent.com/<用户名>/<仓库名>/main/data/latest.json
https://raw.githubusercontent.com/<用户名>/<仓库名>/main/data/benchmark_history.json
https://raw.githubusercontent.com/<用户名>/<仓库名>/main/data/brand_history.json
```

- 好处：绕开反爬、字段统一、历史数据自动积累、App 端逻辑极简。
- 首次启动拉全量写入 drift；之后只拉 `latest.json` 做增量更新。
- 拉取失败时用本地缓存，界面顶部提示「数据可能不是最新」。
- raw.githubusercontent.com 在国内可能不稳定，后续可加一条备用路径（GitHub Pages / jsDelivr CDN）。

## 三、页面设计

### 1. 今日（首页）
按回测结论 #5 排序信息层级：**渠道差异（约 40%）远大于择时收益（几个百分点）**，
所以「渠道对比」必须出现在首屏，而不是藏在二级页面。

- 首屏顶部：**渠道对比卡** —— 输入预算，直接显示「品牌店能买 X 克 / 水贝能买 Y 克 / 省 Z 元」
- 次位大卡片：大盘 Au99.99 最新收盘价 + 日涨跌（对比前一日）
- 「首饰金溢价」指标：均价高出大盘 X 元/克（Y%）—— 判断首饰金是否划算的核心
- 品牌比价列表：按首饰金价升序，标出最低价（绿色）与最高价（红色）
  - 每行可展开显示该品牌的金条价、铂金价
- 快捷筛选：`首饰金` / `金条` / `铂金`

### 2. 渠道对比（本项目的差异化功能）
把「同样预算能买多少克」算给用户看：

| 渠道 | 克价模型（可调） |
| --- | --- |
| 品牌店 | 品牌首饰金价 + 工费 |
| 深圳水贝 | 大盘价 + 工费（默认 30 元/克） |
| 银行金条 + 打金 | 大盘价 + 金条加点（默认 12）+ 打金工费（默认 25） |

用户输入预算与目标克重，实时算出各渠道可买克重与差价总额。
所有假设参数（工费、加点）都做成可调设置，默认值写在设置页并注明来源假设。

### 3. 趋势
- 时间范围：30 天 / 90 天 / 1 年 / 3 年 / 全部
- 大盘日线折线（开高低收可用 K 线或面积图）
- 叠加均线 MA20 / MA60
- 指标卡：当前价在所选区间的分位数、距区间高点回撤、20 日波动率
- 品牌历史（数据攒够后）：各品牌首饰金价走势对比

### 4. 提醒
- 策略开关 + 参数配置
- 触发记录：历史上每次提醒的时间与触发价

### 5. 我的（设置）
- 预算与目标克重
- 渠道假设参数（工费 / 加点）
- 一键自检：检测通知权限、省电策略、自启动 —— 小米 HyperOS 必看

## 四、策略引擎（本地计算）

本节参数由 analysis/strategy_backtest.py 用上金所 10 年真实日线回测确定，
完整数据见 analysis/backtest_report.md。**回测推翻了最初凭直觉的设计**，以下为修正后的方案。

### 4.1 回测关键结论（2016-12 ~ 2026-09，2363 个交易日）

| 发现 | 数据 |
| --- | --- |
| 回撤 / 均线类规则跑输「随便哪天买」 | 20 日收益 +0.37%~+0.80%，基准 +1.39% |
| 「历史分位」在黄金上根本不可用 | 1 年窗口跑输基准；3 年 / 5 年窗口**十年触发 0 次**（见 analysis/percentile_report.md） |
| 最有价值的稀有信号 | RSI14<30（10 年 39 次，20 日 +3.02%）；单日跌幅≥2%（51 次，+1.96%） |
| 单点买入事后几乎都「买早了」 | 基准本身 86% 概率在 60 日内出现更低价 |
| 择时收益远小于渠道选择 | 择时几个百分点 vs 渠道差价约 40% |

### 4.2 调整后的提醒策略

| 优先级 | 策略 | 默认参数 | 说明 |
| --- | --- | --- | --- |
| 核心 | 单日大跌 | 跌幅 ≥ 2% | 恐慌日，历史上最有操作性 |
| 核心 | RSI 超卖 | RSI14 < 30 | 稀有，20 日收益最优（基准的 2.2 倍） |
| 核心 | 绝对目标价 | 用户设定（元/克） | 牛市里唯一稳定的锚 |
| 辅助 | 溢价收窄 | 首饰金溢价率回落至近期低位 | 决定「现在买首饰是否划算」 |
| 仅提示 | 回撤 | 近 90 日高点回落 ≥ 8% | UI 须标注「历史上跑输基准」 |
| 仅提示 | 均线 | 收盘 < MA60 | 同上 |
| **不上线** | 历史分位 | —— | 已专项验证：3/5 年窗口十年触发 0 次、1 年窗口跑输基准。详见 analysis/percentile_report.md |

同一策略 24 小时内只提醒一次。**所有策略在 UI 上必须标注为「提示」而非「买入信号」。**

### 4.3 买入辅助 —— 诚实版

「分批买入计划器」：设定总克数与批数，按时间或按回撤触发。

**回测结论与直觉相反**：在本样本（金价单边上涨 +258%）中，
分批买入的每克成本**高于**一次性买入，分批只在 12~19% 的情况下更划算 ——
因为「等待」意味着在更高的价位买入。

因此分批的价值是**降低单点风险**，不是省钱。UI 必须如实说明，**禁止宣传「分批更便宜」**。

## 五、小米 HyperOS 后台保活（必做，否则提醒不响）

小米省电策略会杀后台，导致 WorkManager 定时任务不触发。App 内需要：
1. 引导用户把「省电策略」设为 **无限制**
2. 引导开启 **自启动**
3. 引导在最近任务里 **锁定后台**（下拉图标加锁）
4. 请求 `POST_NOTIFICATIONS` 权限（Android 13+）
5. 提供「立即测试通知」按钮，让用户当场验证是否生效

## 七、风险与注意

- `raw.githubusercontent.com` 国内访问可能间歇性失败 → 必须有本地缓存 + 备用 CDN。
- 品牌报价来自第三方网页，若页面改版解析会失败 → 采集脚本已做「失败保留旧数据」，不会让历史丢失；需要时更新解析规则。
- 香港品牌价格单位是 `HKD/两`，与大陆不同，默认不混在一起比较。
- 本项目提供的是规则化提醒，**不能预测最低点，不构成投资建议**。
